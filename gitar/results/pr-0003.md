<kbd>🔴 High risk</kbd> · Running the exporter on PR-close events with contents:write could let untrusted PR code use the token to alter repository contents.

Adds `scripts/gitar_export.py` and a `gitar-results` workflow that collect Gitar reviews, findings, and fix commits into `gitar/results/` on a schedule and on PR close. Approved with suggestions: fork PR close events will fail the workflow because the token is read-only, so skipping fork close events is the simplest fix. The retry loop in `scripts/gitar_export.py` also retries HTTP 4xx errors like 401, 403, and 404, which should re-raise immediately except for 5xx responses.

<summary>💡 <b>Edge Case:</b> Fork PR close events can't push, so the workflow fails every time</summary>

The repo is public, so outside contributors can open PRs from forks. When one of those PRs closes, the `pull_request` run gets a read-only `GITHUB_TOKEN` even though the workflow asks for `contents: write`. The loop then tries `git push origin HEAD:main` five times, sleeps between tries, and exits 1, which leaves a red run on every fork PR. The 30-minute schedule picks up those results anyway, so the simplest fix is to skip close events that come from forks.

<details>
<summary>Skip fork PR close events. The scheduled run still exports their results.</summary>

````
jobs:
  export:
    if: github.event_name != 'pull_request' || github.event.pull_request.head.repo.full_name == github.repository
    runs-on: ubuntu-latest
````

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/3/files#diff-0182383526d6e5bee0b9ad6c63af22fa3588d73571cb1589813baab820b4b7bfR46-R53">scripts/gitar_export.py:46-53</a></kbd>

`urllib.error.HTTPError` is a subclass of `URLError`, so `except (urllib.error.URLError, TimeoutError)` also catches real HTTP error responses. A bad token (401), a rate limit (403/429) or a wrong repo name (404) gets retried 4 times with backoff before the error is raised. That adds about 12 seconds per call, and the rate-limit case sends even more requests. Re-raise `HTTPError` right away, except for 5xx responses.

<details>
<summary>Retry only network errors and 5xx responses.</summary>

````
except urllib.error.HTTPError as err:
    if err.code < 500 or attempt == attempts:
        raise
    time.sleep(2 * attempt)
except (urllib.error.URLError, TimeoutError):
    if attempt == attempts:
        raise
    time.sleep(2 * attempt)
````
