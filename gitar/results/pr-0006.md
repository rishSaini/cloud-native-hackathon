<details>
<summary>💡 <b>Bug:</b> Late async render overwrites cleanup and leaks the board poller</summary>

`render()` checks `seq !== renderSeq` only before the screen renders. `board.render` is async: it appends its section and then awaits `api.board()`. If the person navigates away during that await, the newer render clears `main` and sets its own `cleanup`. When the board's promise resolves later, line 77 overwrites `cleanup` with the board's stop function. The 5s `/api/board` poll keeps updating detached nodes until the next navigation, and any cleanup the newer screen returned is lost. The stale render also calls `focusScreen` and flips `firstRender`. Fix: check the sequence again after `await screen.render(...)`, and if this render is stale, run the cleanup it returned straight away instead of storing it.


**Throw away the cleanup from a render that a newer navigation has replaced:**
````
const nextCleanup = await screen.render(main, { path, query, navigate });
if (seq !== renderSeq) {
  if (typeof nextCleanup === "function") { try { nextCleanup(); } catch { /* ignore */ } }
  return;
}
cleanup = nextCleanup;
````

<details>
<summary>💡 <b>Bug:</b> Mock search with no match reports "4 talks found"</summary>

When no talk matches, `mock.searchTalks` returns `talks.slice(0, 4)` as `hits` with `total: 0`. `talks.js` builds its summary from `hits.length`, so a query with no matches shows and announces "4 talks found." above four unrelated talks. The "No talks matched" message never appears in demo mode, which is the mode used whenever the search routes are missing or `?mock=1` is set. Fix: return `hits: []` when nothing matches, or add a `note` that says these are suggestions.


**Label the fallback suggestions so the count isn't misleading:**
````
return scored.length
  ? { hits: scored, total: scored.length }
  : { hits: talks.slice(0, 4).map(decorate), total: 0, note: "No talks matched. Here are a few to start with." };
````
