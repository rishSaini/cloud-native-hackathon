> `me` only gets set from `displayId` on the GET /api/card response. The PR description says the real backend doesn't return that field yet. So after a page reload, `me` is null for someone who already has a card, and saving from Edit calls `api.createAttendee()` (POST /api/attendees) again before the PUT. That can mint a new identity and leave behind the existing card, groups and shared links. `loadMe` has the same problem on any GET error: it sets `card = null` and `loaded = true`, so a person who already has a card is sent back into onboarding and a new attendee gets created. Fix: only create an attendee when the card load actually reported none (keep a `hasAttendee` flag set when GET returns a card), and don't cache a failed load.
