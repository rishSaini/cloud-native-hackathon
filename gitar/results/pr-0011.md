<summary>⚠️ <b>Bug:</b> Embedding timeout skips the keyword fallback and returns a 500</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/11/files#diff-8f0bf0767aab6a8e4c833fb2444b1d0a82f3903dae3cf1edab700e17fa3de744R81-R91">backend/app/search/talks.py:81-91</a></kbd>

In elasticsearch-py 8/9, `ApiError` (an HTTP error response) and `elastic_transport.TransportError` (`ConnectionTimeout`, `ConnectionError`) are separate exception trees. The app client is built with `request_timeout=10`. A hybrid search waits on the hosted OpenAI embedding call for the query, so a slow embedding service shows up as `ConnectionTimeout`. `except ApiError` doesn't catch that, so the request returns a 500 instead of falling back to BM25 with `mode: "keyword"`, even though the module docstring and PR description promise that fallback. To fix it, catch `TransportError` as well (or catch `ConnectionTimeout` explicitly) in the hybrid branch. You could also give the hybrid call a shorter per-request timeout, e.g. `es.options(request_timeout=...)`, so the fallback still fits inside the user's wait.

<details>
<summary>Import `TransportError` from elasticsearch and include it in the fallback catch.</summary>

````
except NotFoundError:
    raise
except (ApiError, TransportError) as err:  # embedding service down or slow
    if mode != "hybrid":
        raise
````
