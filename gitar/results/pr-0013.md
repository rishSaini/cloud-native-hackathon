<summary>💡 <b>Bug:</b> Failed msearch sub-searches are silently treated as 'no neighbours'</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/13/files#diff-43050e999e18a8bb84a28124ca1eeb35b06b4d943c659c28ad89000eded17a37R58-R64">backend/app/search/similarity.py:58-64</a></kbd>

`msearch` returns per-search failures as `{"error": ..., "status": ...}` entries in `responses` and does not raise. One example: the semantic query's call to OpenAI hits a rate limit or times out. `resp.get("hits", {}).get("hits", [])` turns each failure into an empty hit list. If inference is down, `similarity_matrix` returns `{}` (or a partial matrix) with no exception, no log line and no error on the span. The solver then groups people with no affinity data, and nobody can tell why. Check each response for `error`, and either raise or record it on the span and log it.
