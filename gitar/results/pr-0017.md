<kbd>🟡 Medium risk</kbd> · The new theme restyles every phone screen and onboarding, so layout or contrast regressions could reduce usability across the app.

Adds a warm paper theme, Fraunces headings, and badge-style name cards across the phone screens, with changes limited to visuals. Approved with a suggestion: `theme.css` overrides the narrow-screen `.tabbar` padding fix from `phone.css` at ≤22rem, so at 200% zoom on a 375px phone the tabs shrink enough that labels like "Report" may no longer fit. Adding a narrow-screen override in `theme.css` to restore zero side padding and reduce the inset would resolve it.

<details>
<summary>💡 <b>Edge Case:</b> Theme tab bar padding overrides the very-narrow (200% zoom) fix</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/17/files#diff-a963cc0aa9f9fdac662158950b457ec8eb19b59b1d6acd45d4c9edbc8033f76fR61-R74">frontend/static/css/theme.css:61-74</a></kbd>

`phone.css:164-165` sets `.tabbar { padding-left: 0; padding-right: 0; }` inside `@media (max-width: 22rem)` so that all five tabs still fit on a phone at 200% zoom. `theme.css` loads later and its unconditional `.tabbar { padding: 0.375rem; left: 0.75rem; right: 0.75rem; }` (lines 61-72) has the same specificity, so it wins at every width. At ≤22rem the bar now loses about 2.3rem (1.5rem of inset, 0.75rem of padding, plus the border). On a 375px phone at 200% zoom (187px CSS), each tab shrinks from ~37px to ~29px. A label like "Report" at 0.6875rem is about as wide as the old tab, so it no longer fits. The PR's check at 375px without zoom doesn't cover this case. Fix: add a narrow-screen override in theme.css that brings back the zero side padding and shrinks the inset.

<details>
<summary>Add after the .tabbar rule in theme.css so the very-narrow layout keeps its space for the tabs.</summary>

````
@media (max-width: 22rem) {
  .tabbar { left: 0.25rem; right: 0.25rem; padding-left: 0; padding-right: 0; }
}
````
