<summary>⚠️ <b>Bug:</b> Stray "0" rendered in climate card when there are no reports</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/19/files#diff-b329a97ccca1ab8ead57a65866a07fbffaff51872bf09864b57565c06ba5147cR51-R54">frontend/static/js/climate.js:51-54</a></kbd>

In `climateView`, the last child is `chips.length && age != null ? … : null`. When `chips.length` is 0, the expression evaluates to the number `0`. `h()` only skips `null` and `false`, so it appends a text node "0" under "No reports about this room yet." This is easy to hit: the mock seeds every fourth room with `{}`, and any real room without reports does the same. Use a boolean check instead.

````
chips.length > 0 && age != null ? h("p", { class: "report-age muted" }, `Reported by attendees ${ago(age)}`) : null,
````

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/19/files#diff-61f21c0aab67533cf5c0acb93a2255dea4f5af5570eab8579f5677afe2769a8cR296">frontend/static/js/mock-api.js:296</a></kbd> <kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/19/files#diff-61f21c0aab67533cf5c0acb93a2255dea4f5af5570eab8579f5677afe2769a8cR496">frontend/static/js/mock-api.js:496</a></kbd> <kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/19/files#diff-61f21c0aab67533cf5c0acb93a2255dea4f5af5570eab8579f5677afe2769a8cR536">frontend/static/js/mock-api.js:536</a></kbd>

With this PR, `reportRoom('access_blocked')` creates an incident with `type: "access"`. `climateFor` then sets `captions = "down"` for any unresolved incident, whatever its type, and `decorate` adds the `captions-down` badge the same way. So an elevator report makes the Now screen and search results say the room's captions are down. That is the kind of unconfirmed accessibility claim the PR says it avoids. Only treat captions as down when the incident type is captions.

<details>
<summary>Only captions incidents set captions to down (apply the same check in decorate)</summary>

````
const captionsDown = r.incident && r.incident.state !== "resolved" && r.incident.type === "captions";
const captions = captionsDown ? "down" : c.captions || null;
````

<summary>💡 <b>Edge Case:</b> Density bar shows "NaN% full" when the API sends seats but not taken</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/19/files#diff-55599e1384b0aa31539caf3a5f4d614e3564dcff0ca95eb9f6999d9f9be3a964R204">frontend/static/js/screens/now.js:204</a></kbd> <kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/19/files#diff-b329a97ccca1ab8ead57a65866a07fbffaff51872bf09864b57565c06ba5147cR27-R30">frontend/static/js/climate.js:27-30</a></kbd>

The backend contract says `seats` and `taken` are both optional. `now.js` passes `room.taken` to `densityBar` without a fallback, unlike talks.js, which uses `talk.taken || 0`. If `seats` is set and `taken` is missing, `taken / seats` is NaN, so the bar's width becomes `NaN%` and the text reads "NaN% full · NaN seats left". Guard inside `densityBar` itself, so every caller is covered.

<details>
<summary>Default missing taken to 0 inside densityBar</summary>

````
export function densityBar(taken, seats) {
  if (!seats) return null;
  taken = Number(taken) || 0;
````
