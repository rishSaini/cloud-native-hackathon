<kbd>🟡 Medium risk</kbd> · Adding terminal commands that change the attendee’s next-break RSVP could unintentionally remove or re-add them to a scheduled break.

Adds a kubectl-style terminal drawer to the header with `get pods`, `get nodes`, `describe node/room-251`, `drain`/`uncordon` and `help` commands, using only random IDs and reported room facts. Approved with suggestions: `drain attendee/me` and `uncordon attendee/me` still RSVP to the last break after it has ended and report success, so the code in `frontend/static/js/kubectl.js` should check that the break is still upcoming and return an error like `error: no upcoming break rounds` instead.

<details>
<summary>💡 <b>Edge Case:</b> drain/uncordon RSVP to an ended break once the last break is over</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/20/files#diff-0f97cde9444e95fda4d38195b32a131d9242d0d8248df611c55072cb32c1dd30R92-R102">frontend/static/js/kubectl.js:92-102</a></kbd>

`nextBreak()` in slots.js falls back to `BREAKS[BREAKS.length - 1]` after every break has ended. So once the last break is over, `kubectl drain attendee/me` and `uncordon attendee/me` still call `api.rsvpBreak` for that finished break. They then report success ("You're in for brk-…" or "evicting attendee/me from …"), which isn't true. Check that the break hasn't ended yet, and if it has, return a kubectl-style message like `error: no upcoming break rounds` without making the RSVP call.

<details>
<summary>Guard against the past-break fallback (export BREAK_MINUTES from slots.js or add a helper there).</summary>

function upcomingBreak() {
  const brk = nextBreak();
  const ends = Date.parse(brk.startsAt) + BREAK_MINUTES * 60000;
  return Date.now() < ends ? brk : null;
}
// in drain/uncordon:
const brk = upcomingBreak();
if (!brk) return "error: no upcoming break rounds to schedule";
