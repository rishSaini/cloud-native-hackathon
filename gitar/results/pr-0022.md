Changes are requested because the exchange gets stuck: `POST /api/connections` goes to the real server while `GET /api/connections` falls back to the mock, which always returns an empty list, so the "Waiting for them to agree…" state never clears and the poll runs indefinitely. Fix by keeping both calls in the same mode (or showing a clear "not available yet" state for `connections`) and adding a timeout or exit from the exchanging state.

`POST /api/connections` already exists on the server, but `GET /api/connections` is new and not confirmed yet. Until the backend adds it, FastAPI will answer GET on that POST-only path with 405 `{"detail":"Method Not Allowed"}`. `request()` turns that into `MissingRoute`, so `connections` falls back to the mock (api.js:58-61, 76-78). Meanwhile `proposeConnection` goes to the real server and never touches `myConnections` in the mock. `mock.connections()` therefore always returns `[]`: `refreshConnections` never sees anyone connected, `exchanging` stays true, the button shows "Waiting for them to agree…" forever, and the 3s poll runs for as long as the screen is open. People you've met also stays empty even after a real mutual connection. The fix is to keep the two methods in the same mode: either mark `proposeConnection` as mocked when `connections` falls back, or skip the mock fallback for `connections` and show a clear "not available yet" state. A timeout or way out of the `exchanging` state would also help.

<details>
<summary>Use the mock for both methods once GET is missing, so they share state</summary>

connections: withFallback("connections", async () => {
  try {
    const data = await request("GET", "/api/connections");
    return Array.isArray(data) ? data : data?.connections || [];
  } catch (err) {
    if (err instanceof MissingRoute) useMockFor("proposeConnection");
    throw err;
  }
}),
