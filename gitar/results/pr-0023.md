<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/23/files#diff-815175ac6407f00b02e11e22868af57f5a05fd5e870eb19312d9701c5017d42eR7-R8">scripts/kwok-spike.sh:7-8</a></kbd> <kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/23/files#diff-815175ac6407f00b02e11e22868af57f5a05fd5e870eb19312d9701c5017d42eR16-R20">scripts/kwok-spike.sh:16-20</a></kbd>

The safety check at `scripts/kwok-spike.sh:17` uses `grep -qE '\.cnh\.radarhq\.io|127\.0\.0\.1'` with no anchors. Any server URL that merely *contains* one of those strings gets through, for example `https://x.cnh.radarhq.io.other-domain.com` or any `127.0.0.1` port-forward or `kubectl proxy` tunnel to some other cluster. The script then installs cluster-wide CRDs, ClusterRoles and an `exempt` FlowSchema, and creates a Node there. That breaks the header's promise of "never anything else" and the rule against touching another team's cluster. Fix: match the host part of the URL exactly.

<details>
<summary>Pull out the hostname and match it exactly, with anchors.</summary>

````
host="${server#*://}"; host="${host%%[:/]*}"
if ! [[ "$host" =~ ^[a-z0-9-]+(\.[a-z0-9-]+)*\.cnh\.radarhq\.io$ || "$host" = 127.0.0.1 ]]; then
  echo "Refusing: $server is not the hackathon cluster or a local kind cluster." >&2
  exit 1
fi
````
