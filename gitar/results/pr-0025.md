<summary>💡 <b>Bug:</b> Resize snap ignores groupId, so grouped stars glide back after resize</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/25/files#diff-56de900a06388c4f9ae614a3f0c2cb01cc60bdb7070dd998c06bfba6046c6bd0R136-R145">frontend/static/js/board/sky.js:136-145</a></kbd> <kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/25/files#diff-56de900a06388c4f9ae614a3f0c2cb01cc60bdb7070dd998c06bfba6046c6bd0R296-R302">frontend/static/js/board/sky.js:296-302</a></kbd>

`targetFor` now sends a star with a `groupId` to its table. But the resize snap still calls `targetFor({ displayId, roomId: s.roomId })` with no `groupId`. Every grouped star snaps to a room position, and then `placeStars` sees a different target and animates it back to the table. So on any resize or rotation during a break, all constellations fly in from the rooms, which goes against the "no glide on resize" comment. The fix is to store `groupId` on the star in `placeStars` and pass it to the snap.

<summary>💡 <b>Edge Case:</b> New group slot uses list index, can collide with a surviving group</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/25/files#diff-56de900a06388c4f9ae614a3f0c2cb01cc60bdb7070dd998c06bfba6046c6bd0R321-R329">frontend/static/js/board/sky.js:321-329</a></kbd>

A new group gets `slot: i`, where `i` is its index in the current `groupList`. Once any earlier group drops out (for example, when someone leaves on a real backend), the indices shift. A new group at index `i` then lands in a slot that a surviving group already holds, and the two constellations draw on top of each other. A fix is to give each new group the lowest slot that no live group in `groupPos` is using.

<details>
<summary>Allocate the first free slot</summary>

````
const used = new Set([...groupPos.values()].map((p) => p.slot));
let next = 0;
for (const g of groupList) {
  if (groupPos.has(g.id)) continue;
  while (used.has(next)) next++;
  used.add(next);
  groupPos.set(g.id, { ...slotCenter(next), slot: next, t0: performance.now() });
}
````

<summary>💡 <b>Edge Case:</b> Demo keys inject mock snapshots into a live (non-mock) board</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/25/files#diff-8376d7a6d890da5ba264124f0da793d2d4d621c103171c33050f6b7c60c1b195R285-R299">frontend/static/js/board/board.js:285-299</a></kbd>

The keys in `?demo=1` always call the mock `demo.*` functions, and these emit `board` events. `stream.js` always forwards mock events to subscribers (`mockOn` is wired even when not in mock mode), so `setBoard` swaps the real board for fake rooms and attendees. While SSE is live, polling is paused, so the fake data stays until the next real board event. The F key also shows "0 people alone" over real numbers. The keys should be limited to when `isMock()` is true, or `demo=1` should imply mock mode.
