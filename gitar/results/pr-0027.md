Adds the venue data file, capability code map, and a generator for 34 KWOK Nodes plus two priority classes. Changes are requested because the `affinity-hard-requirement` PriorityClass description states that its Pods are attendees with access needs, which exposes sensitive attendee information through cluster-readable objects and conflicts with the rule that access needs never reach Kubernetes objects. Replace the description with neutral wording before merge.

`affinity-hard-requirement` has the description "Attendees with access needs: placed first, never bump anyone." PriorityClasses are cluster-readable objects, and every attendee Pod will carry `priorityClassName`. So anyone who runs `kubectl get priorityclass -o yaml` and looks at a Pod (Radar, MCP, AI investigations) learns in plain words that this attendee has access needs. That breaks the rule that access needs never reach Kubernetes objects (docs/tasks/rishabh.md:183) and the promise in capabilities.py:3-5. The class name is set by the task spec, but the description and the header comment add the explicit statement. Fix: use neutral wording that does not describe the people in each class.

description: "Placement tier A: scheduled first, never preempts."
