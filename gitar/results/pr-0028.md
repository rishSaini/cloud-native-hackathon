<summary>⚠️ <b>Bug:</b> Failed card load tells cardholders they have no card to delete</summary>

`loadMe()` returns `{ error }` and leaves `card` unset when the request fails for any reason other than a 401, such as being offline or a 5xx (store.js:25). In that case the store deliberately does not treat the user as having no card. `settings.js` ignores `error`, so when `card` is null it shows "You don't have a card right now, so there's nothing to delete." and hides the delete button. That is wrong for an existing cardholder, and it removes the only way to delete their data from this screen. The Card screen already handles this case with `if (loaded.error) loadErrorView()`. Do the same here, or show a retry message in the danger zone when `error` is set.


**Check the load error before rendering the delete section:**
````
const { card, error } = await loadMe();
// ...in the danger-zone section:
h("p", { class: "muted" }, error
  ? "We couldn't check your card right now. Check your connection and open Settings again."
  : card
    ? "This removes your card, ... any time."
    : "You don't have a card right now, so there's nothing to delete."),
card && !error ? h("button", { /* ... */ }, "Delete my card and data") : null,
````
