<summary><b>Code Review</b> <kbd>🚫 Blocked</kbd> <kbd>0 closed / 5 findings</kbd></summary>

<kbd>🔴 High risk</kbd> · The cluster-wide controller role can patch Nodes and create or delete Pods across namespaces, so a compromised controller could disrupt workloads.

Adds talk placement: attendee Pods with affinity rules, seat bookings in a new `placements` table, and a `GET /api/placements/current` endpoint. Review is blocked by two critical issues: the controller Deployment never sets `DATABASE_URL`, so placement always fails, and the ClusterRoleBinding still targets the `team-__TEAM__` placeholder namespace instead of `team-coffeecon`, so the controller gets 403s. Also open: the ClusterRole grants Pod create/delete cluster-wide and should be namespaced, the new `/api/placements` routes lack tests, and Pending options are not refreshed when the reason text is unchanged.

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/29/files#diff-6408806cd940890439c2f4bd2034bb840fcb65556716c96701412c022899596aR40-R54">deploy/controller.yaml:40-54</a></kbd> <kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/29/files#diff-5f425d1124e6eb214e1ca029a721881ccbebc9fbff50f6702b0631411c5bfd2eR17-R21">backend/app/db/__init__.py:17-21</a></kbd> <kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/29/files#diff-2d030b0c8ba27486b119f617dc08a929ca92bb568b7563adc908fc7c4d3753efR70">backend/app/controller/placement.py:70</a></kbd> <kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/29/files#diff-6cc49fed2ccda7a27296319cfac8e87bbc8a7bd95dc1b649fb9bfac259f5468fR59-R64">backend/app/controller/loop.py:59-64</a></kbd>

`reconcile_placements` calls `pool()`, and `database_url()` raises `RuntimeError` when `DATABASE_URL` is unset. `deploy/deployment.yaml` adds `DATABASE_URL` from Secret `db-app`, but `deploy/controller.yaml` only has `envFrom: app-credentials` (optional) and no `DATABASE_URL`. In the cluster, every pass logs `reconciler placement failed`. `run_once` catches that error, so `/healthz` still reports healthy while no Pod is ever created. Fix: add the same `secretKeyRef` env var to the controller container.

<summary>🚨 <b>Bug:</b> ClusterRoleBinding names namespace team-__TEAM__, which setup has replaced</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/29/files#diff-b30932df3b72e0442f9a01aeaf9f243f19659b0b665af3b0c4ba2dfcc2fe3896R33-R36">deploy/rbac.yaml:33-36</a></kbd> <kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/29/files#diff-b73d35871b29b22f3a3720154ad3b1f40bbd6ac482b4a4fdee49c0ad75a149dbR6">deploy/kustomization.yaml:6</a></kbd>

`scripts/setup.sh` has already run on this repo: `kustomization.yaml` now has `namespace: team-coffeecon`. The new `deploy/rbac.yaml` still binds subject `affinity-controller` in `team-__TEAM__`. Kustomize's namespace transformer does not rewrite the namespace of this ClusterRoleBinding subject (it is neither empty nor `default`). So the real ServiceAccount in `team-coffeecon` gets no permissions. Every `list_node`/`list_namespaced_pod` call returns 403, and the controller cannot place anyone. Fix: replace the placeholder with `team-coffeecon`.

<details>
<summary>⚠️ <b>Security:</b> ClusterRole lets the controller create/delete Pods in every namespace</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/29/files#diff-b30932df3b72e0442f9a01aeaf9f243f19659b0b665af3b0c4ba2dfcc2fe3896R7-R21">deploy/rbac.yaml:7-21</a></kbd>

The `pods` (create, delete) and `events` rules are in a ClusterRole bound with a ClusterRoleBinding. The controller's ServiceAccount can therefore create arbitrary Pods in any namespace, including kube-system, and delete other teams' workloads. It only manages attendee Pods in its own namespace. Only `nodes` and `nodes/status` need cluster scope. Fix: move the pods and events rules into a namespaced Role and RoleBinding.

</details>

<details>
<summary>⚠️ <b>Quality:</b> New /api/placements routes have no tests</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/29/files#diff-3f500cd5a79f57b93cd05e945f63792c50ccc5b4dde5704a1491afe81235d93cR22-R36">backend/app/placements/routes.py:22-36</a></kbd>

The project rules say every new API route needs a test in `backend/tests/`. This PR adds `POST /api/placements` and `GET /api/placements/current` but no test that calls them. The `to_response` mapping (Scheduled/Pending shape, kubectl line, fallback when only a request exists) and slot validation are never exercised. Fix: add route tests that override `current_attendee_id` and `get_es` (FakeES), and monkeypatch `pool()` with a fake connection, so no Postgres or Elasticsearch is needed.

</details>

<details>
<summary>💡 <b>Edge Case:</b> Pending options are only recomputed when the reason text changes</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/29/files#diff-2d030b0c8ba27486b119f617dc08a929ca92bb568b7563adc908fc7c4d3753efR129-R141">backend/app/controller/placement.py:129-141</a></kbd>

The guard `known.get(key)[2] != reason` skips the UPDATE whenever the plain-language reason is unchanged. Once a Pending attendee has 'The matching talks ... are full' plus three options, those `seatsLeft` values and rooms are never refreshed, even after the rooms fill up or seats free up. The attendee keeps seeing options that may no longer have space. Fix: also compare the stored options, or always refresh options for Pending placements, since `free_by_slot` is already cached per slot.

</details>
