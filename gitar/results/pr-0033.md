<kbd>🔴 High risk</kbd> · Staff login accepts the shared token in a URL query parameter, which could leak credentials and enable unauthorized incident changes.

Adds the public board endpoint, returning the four contract rooms for the current slot from one msearch with room state, active incidents, recent report freshness, and a board summary, with no identifiers exposed. Changes are requested before merge: the staff token is passed in the login URL query string where it can reach logs and traces, concurrent reports can open duplicate incidents through a check-then-insert race, the board freshness aggregation is not limited to contract rooms and can drop them from the top 50, and new spans and metrics lack the required `talkscout.` or `search.` prefix.

<details>
<summary>⚠️ <b>Security:</b> Staff token sent in the URL query string ends up in logs and traces</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/33/files#diff-40706f38b703cef839b8e29b85c7eb580111a9f5dd93989b9010f18c7b812e49R32-R38">backend/app/incidents/routes.py:32-38</a></kbd>

`GET /api/staff/login?token=...` puts the shared STAFF_TOKEN in the URL. The app runs under `opentelemetry-instrument` with the FastAPI instrumentation (backend/start.sh). That instrumentation records the request target, query string included, on the server span, and uvicorn's access log prints the full path. So every staff login sends the secret to Dash0 and to pod logs, and the repo is public. Take the token in a POST body (or the `X-Staff-Token` header) and set the cookie from there.

<summary>Accept the token in a POST body instead of the query string</summary>

````
class Login(BaseModel):
    token: str


@router.post("/api/staff/login")
def staff_login(body: Login, request: Request, response: Response):
    if not _valid(body.token):
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "Wrong staff token")
    proto = request.headers.get("x-forwarded-proto", request.url.scheme)
    response.set_cookie(COOKIE, body.token, httponly=True, samesite="strict", secure=proto == "https", max_age=60 * 60 * 12)
    return {"ok": True}
````

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/33/files#diff-4ed82c65b6434505a25dc030a635b2387473cbec77ecae95afa337162d09ba4cR47-R55">backend/app/incidents/store.py:47-55</a></kbd> <kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/33/files#diff-c8af2d7f2593c8f9f941beef34a083d5d703eeaff10990e5412051436fa74ae6R177-R185">backend/app/reports/state.py:177-185</a></kbd>

`open_incident` searches for an active incident, then indexes a new doc under a random `inc-<uuid>` ID. Two app replicas run at once. If two `captions_down` reports arrive together, both recomputes read a previous state that is not `down`, both searches come back empty, and both create an incident. Staff then see the same outage twice, which breaks the "one active incident per room and kind" rule. Use a deterministic ID for the active incident (for example `inc-{room}-{kind}-{n}`, or a lock doc made with `op_type="create"`) so the second writer gets a 409 conflict, then return the existing incident.

<summary>💡 <b>Edge Case:</b> Board freshness aggregation isn't limited to contract rooms</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/33/files#diff-6b7528312c5b770f0747e72401e80739191e721b8c799bfa34fe40b17935b740R34-R37">backend/app/board/routes.py:34-37</a></kbd> <kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/33/files#diff-ecf155e1911450cf410222dcfd2fa44a6ef93eb98935f305e6468ca0ff61ea83R38">backend/app/reports/routes.py:38</a></kbd>

The reports route accepts any `room-[a-z0-9-]{1,30}` ID, but the board's `max(@timestamp)` aggregation runs over every room and keeps only the top 50 buckets by doc count. If reports go to more than 50 rooms in 30 minutes (stray or malicious IDs), contract rooms can drop out of the top 50, and their `reportedMinutesAgo` shows `null` even though they have fresh reports. Add `{"terms": {"room": ROOMS}}` to the query's filter so the aggregation only covers the 4 board rooms.
