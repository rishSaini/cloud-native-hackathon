Changes are requested for three open findings: the 10s client timeout turns slow completions into an unhandled 500 instead of the 503 fallback, the staff token is passed in a GET query string where it reaches access logs and Dash0, and the new spans and metrics don't use the required `talkscout.` or `search.` prefix.

<details>
<summary>⚠️ <b>Bug:</b> Ask: client times out at 10s, so slow completions return 500, not 503</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/34/files#diff-98943d9c76d77b55fcefbbf54aad2c7ba7c51d3f20b77856fb6e4bbb56bf062dR73-R80">backend/app/ask/routes.py:73-80</a></kbd>

`get_es()` builds the shared client with `request_timeout=10`. The `timeout="30s"` passed to `inference.completion` is only the server-side timeout. When the OpenAI call takes longer than 10 s, the client raises `ConnectionTimeout`, which is an elastic_transport `TransportError` and not an `ApiError`. The `except ApiError` misses it, so the request fails with an unhandled 500 and the UI never gets the 503 it uses to fall back to search. The PR's own measurements are already 3.7 to 5 s, so this is close to happening. A response with an empty `completion` list also raises IndexError and returns 500. Fix: raise the client timeout for this one call, and also catch TransportError and malformed responses.

<details>

<summary>⚠️ <b>Security:</b> Staff token sent in a GET query string ends up in access logs</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/34/files#diff-40706f38b703cef839b8e29b85c7eb580111a9f5dd93989b9010f18c7b812e49R32-R38">backend/app/incidents/routes.py:32-38</a></kbd> <kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/34/files#diff-a3046da0d15a27e89f2afe639b25748a7ad4d9290af3e7b1b6c1a5533c8f0a8c">.env.example</a></kbd>

`GET /api/staff/login?token=...` puts the shared STAFF_TOKEN in the URL. Uvicorn access logs record the full path and query string. Logging auto-instrumentation is on (`OTEL_PYTHON_LOGGING_AUTO_INSTRUMENTATION_ENABLED=true`), so the token is exported to Dash0. Gateway/proxy logs and browser history also keep it, which lets anyone with log access act as staff. Fix: accept the token in a POST body (or a header), then set the cookie from that.
