<summary>✅ <b>Bug:</b> Ask: client times out at 10s, so slow completions return 500, not 503</summary>

> <kbd>📄 backend/app/ask/routes.py:73-80</kbd>
> `get_es()` builds the shared client with `request_timeout=10`. The `timeout="30s"` passed to `inference.completion` is only the server-side timeout. When the OpenAI call takes longer than 10 s, the client raises `ConnectionTimeout`, which is an elastic_transport `TransportError` and not an `ApiError`. The `except ApiError` misses it, so the request fails with an unhandled 500 and the UI never gets the 503 it uses to fall back to search. The PR's own measurements are already 3.7 to 5 s, so this is close to happening. A response with an empty `completion` list also raises IndexError and returns 500. Fix: raise the client timeout for this one call, and also catch TransportError and malformed responses.
