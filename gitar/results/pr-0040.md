<summary>⚠️ <b>Bug:</b> Incident SLO check fires on acknowledged incidents, not on unacknowledged ones</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/40/files#diff-72c47bb3fd524fdfb3235732702bc5f0fa3cc5e767a01fffc824fdd9115b601fR55-R63">observability/dash0/checks/affinity-slos.yaml:55-63</a></kbd> <kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/40/files#diff-45d46d4727f58dbf24aea766fc77e186639e01701fe4c8bf8028c88e4577b199R43">observability/dash0/README.md:43</a></kbd>

The SLO in docs/AFFINITY.md is "captions incidents acknowledged, 95% within 5 minutes", and the lifecycle is `open -> acknowledged -> resolved`. The rule's own comment says `affinity_incidents_open` counts open *and acknowledged* incidents, so `min_over_time(affinity_incidents_open[5m]) > 0` keeps firing (as critical) after staff acknowledge an incident, until it is resolved. The summary text even says "unresolved", which is a different SLO. The gauge is also an aggregate, so a stream of different incidents that are each acknowledged quickly keeps it above zero and the alert fires anyway. Fix: alert on a gauge or label that counts only incidents still in state `open` (e.g. `affinity_incidents_open{state="open"}`, or a separate `affinity_incidents_unacknowledged` gauge). Then update the README row and the summary to match.

<details>
<summary>Alert only on incidents that are still unacknowledged (needs the gauge to carry a state label)</summary>

# Incident response: captions or access incidents get acknowledged within 5 minutes.
- alert: AffinityIncidentNotAcknowledged

    min_over_time(affinity_incidents_open{state="open"}[5m]) > 0
  for: 0m
  labels: {severity: critical, slo: incident-response}
  annotations:
    summary: "An accessibility incident has stayed unacknowledged for 5 minutes"
