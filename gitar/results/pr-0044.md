<kbd>🟡 Medium risk</kbd> · Room-state taints and capability-triggered Pod deletion reroute attendees; stale or incorrect room signals could disrupt valid placements or leave attendees unplaced.

Adds reroute handling for room closures and lost capabilities, moving affected Pods to a new Node and recording the move in a `moves` table with a `moved` notification. Changes requested: a failed Pod delete rolls back move counts for Pods already deleted in the same pass, which can break the once-per-slot rule and should be fixed by committing each increment before deleting and ignoring 404s. Also, the new span `k8s.node.taint` and histogram `affinity_reroute_duration_seconds` lack the required `talkscout.` or `search.` prefix.

<details>
<summary>⚠️ <b>Bug:</b> A failed Pod delete rolls back move counts for Pods already deleted</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/44/files#diff-1cdbd0fc1b7271e4a476cb9373c81d459b9151b4e77adacdecada58a675e990fR45-R59">backend/app/controller/reroute.py:45-59</a></kbd>

`reconcile_reroutes` runs the whole loop in one `pool().connection()` transaction. The pool isn't autocommit, so the `moves` increments only commit when the block exits normally. Each Pod's `delete_namespaced_pod` call goes out to Kubernetes right away. If a later delete raises (for example a 404 because the NoExecute eviction or placement removed the Pod between the list and the delete, or any API error), psycopg_pool rolls back the transaction. That undoes the `count + 1` for every person whose Pod this pass already deleted. On the next lost capability in the same slot they get moved again, which breaks the once-per-slot rule. Fix: commit each person's increment before deleting (`with conn.transaction():` per Pod, or `conn.commit()`), and ignore a 404 from the delete.

<details>
