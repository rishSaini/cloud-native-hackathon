<summary>⚠️ <b>Edge Case:</b> Notifications sent while LISTEN reconnects are lost to open streams</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/48/files#diff-6f0b8681215a45ae4091d499bb6b54e70e6ed99b00c35650e4dbb0d26d40c0f4R49-R58">backend/app/stream/hub.py:49-58</a></kbd>

`pg_notify` only reaches sessions that are listening when it fires. If the LISTEN connection drops (DB failover or restart), `_listen` sleeps 2 s, reconnects and re-issues `LISTEN`, but it never catches up on the gap. SSE clients stay connected through this because their own HTTP connection is fine. Any `placed`/`moved`/`group` notification inserted during the outage never reaches them, and they don't get the latest placement again until they reconnect themselves. A CNPG failover is a normal event, so phones can be left showing a stale room. Fix: on every successful (re)connect, track the max `notifications.id` seen and replay rows with a higher id, or push a resync signal so each subscriber re-sends `latest_placement`.

<details>
<summary>After reconnecting, tell every subscriber to resync (for example with a sentinel the route handles by re-sending latest_placement)</summary>

````
def _listen(self) -> None:
    first = True
    while True:
        try:
            with psycopg.connect(database_url(), autocommit=True) as conn:
                conn.execute("LISTEN affinity")
                if not first:
                    self.resync_all()  # enqueue a RESYNC sentinel to every subscriber
                first = False
                for note in conn.notifies():
                    self.deliver(note.payload)
        except Exception as err:
            log.warning("LISTEN connection lost (%s); reconnecting", type(err).__name__)
            time.sleep(2)
````
