<kbd>🔴 High risk</kbd> · Deleting an attendee cascades through Postgres records, removes its search profile, and schedules Pod removal, potentially permanently erasing related data and workloads.

Adds `DELETE /api/card` that removes an attendee everywhere (Postgres cascade, Elasticsearch person doc, and Pods via a new cleanup reconciler) and clears the session cookie. Changes are requested because the old session cookie remains valid for up to 7 days after deletion, and it can recreate the deleted attendee under the same ID through `PUT /api/card` or `POST /api/attendees`, undermining the deletion and the reconciler's view of valid Pods. Fix by rejecting session IDs absent from `attendees` or by keeping a tombstone list that blocks re-insertion.

<summary>⚠️ <b>Bug:</b> Old session cookie still works after deletion and recreates the attendee</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/49/files#diff-286e12f2e92b654bd5cb72fbc14d1116a89a447a1d4f69a5910c53129ac81ce5R94-R101">backend/app/cards/routes.py:94-101</a></kbd> <kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/49/files#diff-d32b91d914ce408c1a8d4181fc2f8301fa7bb347783d4e934c384068c95d622dR16-R20">backend/app/cards/delete.py:16-20</a></kbd>

Sessions are stateless signed cookies (`current_attendee_id` at `app/auth.py:68-73` only checks the signature). `response.delete_cookie` only clears the cookie in the browser that sent the DELETE. Any other copy of the cookie (another tab or device, or a request already in flight) stays valid for up to 7 days. With that copy, `PUT /api/card` runs `store.save`, which does `INSERT INTO attendees ... ON CONFLICT DO NOTHING` (`store.py:25`), and `POST /api/attendees` calls `ensure_attendee` (`routes.py:59`). Both bring back the deleted attendee under the same ID, so the attendee's data is no longer gone everywhere, and the cleanup reconciler will then treat that attendee's new Pods as valid. Fix: make `current_attendee_id` (or `save`/`ensure_attendee`) reject IDs that are not in `attendees`, or keep a tombstone or revocation list of deleted IDs that blocks re-insertion.
