**Team cluster budget check** (`deploy/`, steady state, replicas included)

| Workload | Requests (CPU / mem) | Limits (CPU / mem) |
|---|---|---|
| app ×2 | 200m / 384Mi | 1000m / 1024Mi |
| controller ×1 | 100m / 192Mi | 500m / 512Mi |
| elasticsearch ×1 | 500m / 2Gi | 1500m / 2Gi |
| postgres (CNPG) ×1 | 100m / 256Mi | 500m / 512Mi |
| room-state-sweep CronJob (1 pod at a time) | 50m / 128Mi | 200m / 256Mi |
| **Total** | **950m / ~2.94Gi** | **3700m / ~4.31Gi** |
| **Budget** | 2 CPU / 4Gi | 4 CPU / 8Gi |

**PVCs:** 2 (Elasticsearch 5Gi, Postgres 1Gi), 6Gi in total. The budget is 4 PVCs and 20Gi.

All containers define requests and limits, and the steady-state totals are within budget.

The one-off Jobs touched by this PR (`db-migrate-001`, `es-setup-001`) add 150m / 256Mi in requests and 750m / 512Mi in limits while they run. If both run at once, the CPU limits reach about 4450m, which is over the 4 CPU limit budget. Run them one after the other, or when the CronJob isn't running, to stay within budget.

This PR changes only a namespace, an image and an RBAC subject, so it doesn't change any resource numbers.
