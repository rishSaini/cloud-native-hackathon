<summary>💡 <b>Bug:</b> _last_taken cache updated before commit; samples lost on rollback</summary>

<kbd>📄 <a href="https://github.com/rishSaini/cloud-native-hackathon/pull/58/files#diff-1a58a31156d384c2202c38eacec4ea8a79b791ae3e81f5441b2d4289a4792d0fR81-R95">backend/app/controller/insights.py:81-95</a></kbd>

`_last_taken[r["node"]]` is updated right after each INSERT, but the transaction only commits when the `with pool().connection()` block exits. If a later statement fails (the seat_waits query or insert, or a DB error), the occupancy inserts roll back while the in-memory cache keeps the new counts. Later passes see no change and never write the sample, so `GET /api/insights` shows a stale `taken` for that room until its count changes again. Build a pending dict inside the block and merge it into `_last_taken` only after the block exits cleanly.

<details>
<summary>Update the cache only after the transaction commits</summary>

````
pending: dict[str, int] = {}
with pool().connection() as conn:
    ...
    for r in rows:
        if _last_taken.get(r["node"]) != r["taken"]:
            conn.execute(INSERT_SAMPLE, (...))
            pending[r["node"]] = r["taken"]
    ...
_last_taken.update(pending)  # only after commit
````
