<kbd>🟡 Medium risk</kbd> · Replacing card fields with a multi-step chat changes how profile answers and matching consent are collected, so users could leave onboarding incomplete.

Replaces the fixed-question card editor with a chat-style flow (no AI, no network calls until "Make my card" saves via `PUT /api/card`) and removes the Now tab, with Card as home. Two minor open suggestions: the required name check can be bypassed by editing another answer while the name is blank, so `onDone` should block on an empty name or restore the last committed value; and `/talks` still maps to the removed `now` tab in `TAB_FOR` in `main.js`, so no tab is highlighted there, and the `/now` route should be dropped or redirected.

The change is approved with these suggestions.

The `input` listener writes `draft[q.key] = input.value` on every keystroke, and the required check runs only on submit. Here is how a blank name gets through: someone clicks Edit on their name and clears it, then clicks Edit on another answer (those buttons stay visible while editing) and saves. The name now shows as "Skipped", `advance()` goes to the consent turn, and "Looks good, next" moves on to save a card with an empty name (the bubble also reads "Lovely, ."). One fix is to block `onDone` while the name is blank. Another is to put back the last committed value when someone leaves a question without submitting it.

<details>

onclick: () => {
  const missing = QUESTIONS.findIndex((q) => q.required && !(draft[q.key] || "").trim());

  onDone?.();
}
